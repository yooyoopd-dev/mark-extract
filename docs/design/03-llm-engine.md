# 03 — LLM 엔진 (CLI 서브프로세스)

문서 하나를 로컬 파서로 처리할지 LLM으로 처리할지는 **문서 단위로 선택**한다 (결정 7). 기본값은 설정에, 개별 변경은 인스펙터에 있다.

LLM은 **HTTP API가 아니라 CLI 서브프로세스**로 구동한다 (결정 8). 사내망에서 외부 API 키 사용이 제한되고, 사용자가 이미 인증해 둔 CLI를 그대로 쓰는 편이 현실적이기 때문이다.

> **비결정성**: LLM 엔진은 같은 문서를 다시 변환해도 다른 결과를 낼 수 있다. 재현 가능한 결과가 필요하면 로컬 엔진을 쓴다. 이 사실을 인스펙터의 엔진 선택 옆에 표시한다.

---

## CLI 탐색

```ts
resolveCli(name: string, windowsCandidates: string[]): Promise<string>
```

Windows에서는 `claude.cmd` → `claude.exe` → `claude` 순으로 시도한다. npm 전역 설치는 `.cmd` 셰임을 깔기 때문에 확장자 없는 이름만 찾으면 놓친다.

결과는 캐시하되, **캐시된 경로가 더 이상 존재하지 않으면 무효화**하고 다시 찾는다. 사용자가 CLI를 재설치하거나 버전 관리자가 경로를 옮기는 일이 있다.

찾지 못하면 "설치되지 않음"이 아니라 **무엇을 어떻게 확인했는지**까지 담은 진단 리포트를 만든다. 사내망 PC는 로그 파일을 반출할 수 없어 화면에서 읽고 옮겨 적을 수 있어야 한다.

## 프로바이더별 기동

| 프로바이더 | 인자 | 출력 형식 |
|---|---|---|
| `claude` | `-p --output-format stream-json --input-format stream-json --verbose --model <m>` | 줄 단위 JSON 이벤트 |
| `gemini` | `--skip-trust --approval-mode plan -o json -m <m>` | JSON |
| `codex` | `-a never exec --json --sandbox read-only --ephemeral --model <m> -` | 줄 단위 JSON |
| `ollama` | `run <model>` (프롬프트는 stdin) | 평문 스트림 |

`gemini`는 Windows에서 직접 실행이 실패하면 `cmd /C <경로>`로 재시도한다.

### claude 출력 파싱

`--verbose`가 켜져 있으면 두 종류의 이벤트가 섞여 온다.

- `stream_event` → `event.content_block_delta` → `delta.text_delta` : **진짜 증분 토큰**
- `assistant` : 진행 중인 메시지 **전체**를 매번 다시 보냄 (증분이 아님)

둘을 그대로 이어 붙이면 내용이 중복된다. 증분 이벤트를 한 번이라도 본 뒤에는 `assistant` 이벤트를 무시하고, 증분이 오지 않는 버전에서는 `assistant`의 **이미 내보낸 접두사를 잘라낸 나머지만** 내보낸다.

`{"type":"system","subtype":"hook_started"|"hook_response"}` 이벤트는 사용자의 훅 stdout 전체를 싣고 오므로 진단에 쓸모가 없고 버퍼만 잡아먹는다. 필터링한다.

### Ollama 이중 경로 (결정 15)

본문 생성은 `ollama run`이 하고, 아래 셋만 `http://localhost:11434`를 쓴다. 전부 루프백이라 외부 통신이 아니며, 설정 화면에 그 사실을 적는다.

| 용도 | 엔드포인트 |
|---|---|
| 설치된 모델 목록 (설정 드롭다운) | `GET /api/tags` |
| 모델 컨텍스트 길이 조회 | `POST /api/show` |
| 입력이 컨텍스트를 넘는지 사전 경고 | 위 값으로 계산 |

HTTP가 응답하지 않으면 CLI 단독으로 동작하되 **"잘림을 감지할 수 없음"** 경고를 남긴다. 컨텍스트를 넘긴 입력이 조용히 잘리면 사용자는 문서 뒷부분이 통째로 빠진 걸 모른다.

> **구현 전 검증 필요**: `ollama run`이 파이프 입력에서 어떻게 종료하고 스트리밍하는지는 실제 실행으로 확인하지 않았다. 6단계 착수 시 검증 항목.

## 입력 모드

### 모드 B — 로컬 파싱 → LLM 재가공

로컬 파서로 Markdown을 뽑은 뒤 그 텍스트를 stdin으로 넘겨 구조·제목 계층·표를 다듬게 한다.

- **모든 프로바이더·모든 포맷에서 동작한다.** 기본값으로 삼는다.
- 입력이 모델 컨텍스트를 넘으면 제목 경계에서 분할해 여러 번 호출하고 결과를 이어 붙인다. 분할 지점은 변환 로그에 남긴다.
- 로컬 파서가 놓친 정보(스캔 이미지 속 글자 등)는 LLM도 복원하지 못한다. 없는 정보를 지어내지 않도록 프롬프트에 명시한다.

### 모드 A — LLM이 파일을 직접 읽기

파일 경로를 주고 CLI가 자기 도구로 열게 한다.

**파일 접근은 임시 폴더로 격리한다 (결정 16).**

```
변환 시작
  → 임시 디렉터리 생성 (변환 1건 전용)
  → 대상 파일 1개만 복사
  → 그 디렉터리를 CLI의 작업 디렉터리로 지정
  → 읽기 계열 도구만 허용, 쓰기·실행·네트워크 도구 차단
  → 변환 종료(성공·실패·취소 모두) 시 디렉터리 삭제
```

이렇게 하면 LLM이 볼 수 있는 것은 변환 대상 하나뿐이고, **원본 문서의 실제 경로도 노출되지 않는다.**

| 프로바이더 | 모드 A 처리 |
|---|---|
| `claude` | 도구를 전부 막는 대신 **읽기 전용 프로필**을 따로 둔다. 나머지 격리(`--setting-sources project`, `--no-session-persistence`, `--disable-slash-commands`)는 유지 |
| `codex` | `--sandbox read-only`가 이미 읽기 전용. 작업 디렉터리만 임시 폴더로 지정 |
| `gemini` | `--approval-mode plan`에서 파일 읽기가 승인 없이 되는지 실행 전 진단으로 확인 |
| `ollama` | **불가.** 파일 읽기 도구가 없다. UI에서 모드 A 선택을 차단한다 |

### 포맷 미지원 시 (결정 17)

프로바이더가 해당 포맷을 읽지 못하면 **자동으로 모드 B로 넘어가지 않는다.**

- 문서를 `failed` 상태로 두고, 실패 화면에 사유와 함께 **'모드 B(로컬 파싱 → LLM)로 재시도'** 버튼을 띄운다
- 디자인의 실패 화면 2버튼 구조(`retryBtn` / `retryPlain`)를 그대로 쓴다
- 배치 변환 중이면 해당 문서만 실패로 남기고 큐는 계속 간다

> **미검증**: 어떤 프로바이더가 어떤 포맷을 읽는지는 확정된 사실이 아니다. claude가 PDF·DOCX를 네이티브로 읽는다는 것 외에는 확인하지 않았다. 6단계에서 포맷 × 프로바이더 매트릭스를 실측해 이 표를 채운다.

| | PDF | DOCX | XLSX | XLS | PPTX |
|---|---|---|---|---|---|
| claude | 가능(알려짐) | 가능(알려짐) | 미검증 | 미검증 | 미검증 |
| gemini | 미검증 | 미검증 | 미검증 | 미검증 | 미검증 |
| codex | 미검증 | 미검증 | 미검증 | 미검증 | 미검증 |
| ollama | 불가 | 불가 | 불가 | 불가 | 불가 |

## 프롬프트

- 출력 언어를 설정(한국어/영어/원문 유지)에 따라 지정한다
- **"Markdown 외에 아무것도 출력하지 말 것"** 을 규약으로 둔다. 설명·머리말·맺음말 금지
- 그럼에도 전체를 ` ```markdown ` 펜스로 감싸는 경우가 있어 후처리에서 벗겨낸다 (→ [01 마크다운 정규화](01-architecture.md#변환-파이프라인))
- 원문에 없는 내용을 추가하지 말 것을 명시한다
- 프롬프트 전문은 설정 화면에서 열람 가능해야 한다. 사내 검수 대상이 될 수 있다

## 오류 진단

종료 코드가 0이 아니거나, 0인데 아무것도 못 받았을 때 다음 순서로 원인을 찾는다.

1. **stderr** — 정석 위치
2. **파싱하지 못한 stdout** — CLI가 진단을 stdout의 JSON 채널로 흘리는 경우가 있다. 파서가 인식 못 한 줄을 상한(4KB)까지 **뒤에서부터** 모아 둔다. 종료 직전 줄이 이유를 말한다
3. **둘 다 비었을 때** — 재현 방법을 안내한다

**인증 실패는 따로 승격한다.** `unauthenticated`, `oauth`, `failed to authenticate` 같은 문구가 잡히면 "CLI 인증이 만료되었습니다. 터미널에서 `claude`를 실행해 로그인한 뒤 재시도하세요"로 바꿔 준다. 앱은 CLI 대신 로그인해 줄 수 없다는 점도 함께 알린다.

**성공했는데 빈 결과**인 경우도 실패로 취급한다. 성공으로 넘기면 빈 마크다운 파일이 저장되고 사용자는 나중에야 알아챈다.
