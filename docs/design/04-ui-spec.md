### 색 이외의 값

반지름·타이포·모션은 원본에서 **토큰이 아니라 리터럴로 흩어져 있다.** 구현 1단계에서 토큰으로 승격하되, **값 자체는 바꾸지 않는다.**

| 갈래 | 원본에서 관찰된 값 | 승격할 토큰 |
|---|---|---|
| 반지름 | 2, 3, 4, 5, 6, 8, 10, 12, 14px, 50% | `--radius-xs`(2) `--radius-sm`(4) `--radius-md`(6) `--radius-lg`(8) `--radius-xl`(12) `--radius-full`(50%) — 5px·10px·14px는 사용처에서 직접 지정 |
| 본문 글꼴 | `Inter, "Segoe UI Variable Text", "Segoe UI", -apple-system, BlinkMacSystemFont, …` | `--font-sans` |
| 고정폭 글꼴 | `"Cascadia Mono", "JetBrains Mono", Consolas, monospace` | `--font-mono` |
| 본문 크기 | 13px가 기본. 11 / 11.5 / 12 / 12.5 / 13.5 / 14 / 15 / 16px | `--text-xs`(11) … `--text-lg`(16) |
| 모션 | `.15s ease`(상태 전환) `.2s ease`(투명도) `.22s cubic-bezier(.2,.7,.3,1)`(패널 슬라이드) `.35s ease-out`(진행 막대) | `--motion-fast` `--motion-base` `--motion-panel` `--motion-progress` |

`prefers-reduced-motion: reduce`에서 모든 전환을 `.01ms`로 줄이는 규칙이 원본에 있다. 유지한다.

## 레이아웃

```
.app                grid-template-rows: 40px | 1fr | 28px
  ├ 타이틀바        40px
  ├ .workspace      grid-template-columns: 248px | 336px | 1fr | 300px
  │   ├ 사이드바     문서 탐색
  │   ├ 목록        검색 · 상태 필터 · 정렬
  │   ├ 뷰어        빵부스러기 · 액션바 · 탭 · 본문
  │   └ 인스펙터     속성 · 추출 옵션
  └ 상태바          28px
```

### 브레이크포인트

원본의 미디어쿼리를 그대로 유지한다. 데스크톱 앱이지만 창을 좁히면 같은 규칙이 걸린다.

| 폭 | 변화 |
|---|---|
| ≤ 1440px | 컬럼 축소 `232 / 312 / 1fr / 284` |
| ≤ 1200px | 인스펙터가 **오버레이 드로어**로 전환 (`translateX(102%)`), 열기·닫기 버튼 노출 |
| ≤ 1024px | 사이드바가 **오버레이 드로어**로 전환, 상태바 일부 항목 숨김(`.sb-hide`) |
| ≤ 768px | 단일 컬럼. 목록/뷰어를 `data-pane`으로 전환, '목록으로' 버튼 노출 |
| ≤ 520px | 타이틀바 앱 이름 숨김 |

필수 검증 폭: **1024 / 1366 / 1440 / 1920**. 어느 폭에서도 가로 스크롤이 생기면 안 된다.

### 상태 매트릭스

모든 상호작용 요소에 `default / hover / focus / active / disabled` 를 둔다. 포커스 링은 항상 보이게 유지한다 (`--accent-ring`).

문서 상태는 4개이며 원본의 색 토큰에 대응한다.

| 상태 | 라벨 | 아이콘 | 색 토큰 |
|---|---|---|---|
| `queued` | 대기 | `i-clock` | `--idle-text` / `--idle-bg` |
| `run` | 변환중 | `i-loader` | `--run-text` / `--run-bg` |
| `done` | 완료 | `i-check` | `--ok-text` / `--ok-bg` |
| `failed` | 실패 | `i-alert` | `--err-text` / `--err-bg` |

목록이 빈 경우(`empty`)와 검색 결과가 없는 경우를 구분한다. 원본에 두 경우의 버튼 문구가 다르게 되어 있다 — "파일 추가" vs "필터 초기화".

### 접근성

- 제목 계층을 유지한다. 목록은 `role="listbox"`/`option`, 탭은 `role="tablist"`/`tab`, 스위치는 `role="switch"` + `aria-checked`
- 모달은 `aria-modal="true"`, 포커스를 가두고 Esc로 닫는다
- 아이콘 전용 버튼에는 전부 `aria-label`이 있다. 원본에 이미 들어 있으므로 이식하면서 빠뜨리지 않는다

## 디자인 대비 변경점

### 1. 뷰어 3번째 탭: '추출 필드' → '변환 로그' (결정 11)

원본의 '추출 필드'는 제목·저자·발행처 같은 의미 필드를 신뢰도 %와 함께 보여준다. 이 방식은 폐기한다 (결정 7 — 문서 단위로 로컬/LLM을 고르는 구조로 바뀌었고, 로컬 파서가 신뢰도 점수를 내지 않는다).

대신 **변환 로그**를 넣는다. 담을 것:

- 사용한 엔진 (`로컬 · opendataloader` / `LLM · claude (모드 A)` 등)
- 실제로 넘긴 인자 — 암호 등 민감한 값은 `***`로 가린다
- 경고 목록 (표 잘림, 이미지 건너뜀 등)
- 소요 시간, 페이지 수
- 실패 시 stderr 원문

사내망 PC는 로그 파일을 반출할 수 없다. 이 탭이 유일한 자가진단 수단이므로 **전체 복사 버튼**을 둔다.

탭 아이콘은 `i-table` → `i-code`로 바꾸고, 원본의 `fieldCount` 배지 자리에는 경고 개수를 표시한다.

### 2. 인스펙터 추출 옵션 개편

| 원본 | 변경 | 이유 |
|---|---|---|
| `ocr` 토글 | **조건부 활성** — PDF이고 hybrid 서버 연결 시에만 | 로컬 파이프라인에 OCR이 없다 (결정 6) |
| `hybridFullPages` 토글 | OCR을 켰을 때만 보인다 | `--hybrid-mode full`. auto가 스캔 페이지를 놓쳤을 때의 탈출구 |
| `useStructTree` 토글 | PDF에서 활성 | OCR과 둘 다 켜면 **구조 트리가 이긴다**는 안내를 띄운다 |
| — | **엔진 선택 추가**: 로컬 / LLM, LLM이면 모드 A·B | 결정 7·10 |
| `chunk` 슬라이더 (청크 크기, 200~2000 토큰) | **제거** | 출력이 Markdown 전용이라 RAG 청킹이 할 일이 없다 (결정 12) |
| `strip` (머리글·바닥글 제거) | 유지 | `--include-header-footer`에 대응 |
| `tables` 선택 | 유지 | `--table-method`에 대응 |
| `images` 선택 | 유지 | `--image-output`에 대응 |

엔진 선택 옆에 **"LLM 엔진은 같은 문서라도 변환할 때마다 결과가 달라질 수 있습니다"** 를 표시한다.

### 3. 설정 화면 신규 추가

원본에 없다. 타이틀바의 `설정` 과 명령 팔레트, `Ctrl+,` 로 연다. 원본의 다이얼로그 스타일(`--surface-dialog`, `--shadow-dialog`)을 그대로 쓴다.

## 설정 화면

### 변환

- 기본 엔진 (로컬 / LLM)
- 출력 경로, 프론트매터 포함 여부, 이미지 처리 기본값
- 동시 실행 수 (1~4), 타임아웃, 파일 크기 상한

### LLM

- 프로바이더 (`claude` / `gemini` / `codex` / `ollama`), 모델, 입력 모드(A/B)
- **Ollama**: 모델 드롭다운은 `localhost:11434/api/tags`로 채운다. *"본문 생성은 CLI가 하고, 모델 목록과 컨텍스트 길이 조회만 루프백 HTTP를 씁니다. 외부로 나가는 통신은 없습니다."* 를 함께 표시. HTTP 미응답 시 CLI 단독 동작임을 알린다
- **모드 A 선택 시**: *"변환할 파일 1개만 임시 폴더에 복사해 전달하며, 읽기 도구만 허용합니다. 원본 파일의 실제 경로는 전달되지 않습니다."* 를 표시한다. LLM이 무엇을 볼 수 있는지 사용자가 알아야 한다. Ollama에서는 모드 A를 비활성화한다
- CLI 탐지 결과 + 진단 리포트 (복사 가능)
  - 탐지는 파일을 찾는 데서 끝나지 않고 **실제로 한 번 띄워 본다**. `.ok` / `.warn`(찾았지만 못 돎) / `.miss`(못 찾음) 세 가지가 서로 다른 조치를 뜻하므로 한 칸으로 합치지 않는다
- 프롬프트 전문 열람

### OCR (hybrid 서버)

exe에 포함되지 않는다는 점을 먼저 알리고, 설치·구동 절차를 화면에서 바로 따라 할 수 있게 둔다.

```
1) 설치   pip install "opendataloader-pdf[hybrid]"
2) 구동   opendataloader-pdf-hybrid --port 5002 --force-ocr --ocr-lang "ko,en"
3) 연결   아래에 http://127.0.0.1:5002 입력 후 [연결 테스트]
```

각 명령에 복사 버튼을 둔다. 연결 테스트 결과(성공/실패/응답 시간)를 표시하고, 실패 시 확인 항목을 나열한다. 연결되면 인스펙터의 OCR 토글이 활성화된다.

**주소가 루프백이 아니면 경고를 띄운다.** `--hybrid-url`은 원격 서버도 받는데, 그 경우 **PDF 원본이 그 host로 전송된다.** README가 "외부와 통신하는 경로는 사용자가 명시적으로 켠 두 가지뿐"이라고 적은 이상, 그 두 번째가 무엇을 내보내는지 화면에 있어야 한다.

주소를 비워 두면 OCR을 쓰지 않는다는 뜻이고, 인스펙터 토글이 잠긴다.

## i18n

- 원본이 한국어이므로 **한국어를 기준 원본**으로 삼고 영어를 대응시킨다
- 키는 화면 단위로 계층화한다 (`list.emptyTitle`, `viewer.tab.log`, `settings.ocr.step1` …)
- 상태·오류 문구는 별도 네임스페이스로 모은다. 파서·CLI 오류 코드가 여기에 대응된다
- 날짜·상대시각·숫자는 `Intl`로 로케일에 맞춘다. 원본의 "방금 전", "3.8초" 같은 표현이 영어에서도 자연스러워야 한다
- 글꼴 스택은 한글·영문 모두 감당한다. Inter는 한글 글리프가 없어 `Segoe UI`가 받아내므로 스택 순서를 바꾸지 않는다

## 진행 표시 (build.8 실측 반영)

사용자가 Ollama 14B 모델에서 "변환하는 중입니다"가 끝나지 않는 것처럼 보인다고
보고했다. 원인의 절반은 **진행 표시가 없어서 느린 것과 멈춘 것을 구별할 수 없는
것**이었다.

### 상태 칩 클래스는 계약이다

원본은 `class="status ${cls}"`다 (`design/index.html:1747`). 4단계 이식에서 이것을
`st`로 잘못 옮겨 적었고, `.st`는 어느 CSS에도 없어서 **칩에 배경색이 없고 스피너도
돌지 않았다** (`.status.run .icon { animation: spin }`).

스모크가 계산된 스타일로 이것을 잡는다 — 칩 배경이 투명이 아닐 것, 변환 중 아이콘의
`animation-name`이 `spin`일 것. 이름이 또 어긋나면 색 토큰 대조로는 안 잡힌다.

### 무엇을 보이나

| 자리 | 내용 |
|---|---|
| 문서 카드 | 상태 칩 + 진행률 바 (`.bar > i`, 원본 그대로) |
| 뷰어 | 경과 시간, 진행률(알 때), 받은 글자 수, 취소 버튼 |
| 변환 로그 | LLM은 **첫 응답까지 걸린 시간**을 남긴다 |

**LLM은 퍼센트를 지어내지 않는다.** 총량을 알 수 없으므로 받은 글자 수와 경과 시간만
보인다. 한 글자도 오지 않은 동안에는 "N초 경과 · 첫 응답을 기다리는 중"이다 — 로컬
모델은 모델을 올리는 동안 아무것도 내놓지 않는다.

진행 이벤트는 250ms마다 묶어 보낸다. LLM 스트림은 글자 단위로 와서 그대로 흘리면
렌더러가 버틸 수 없다.

인라인 `style` 속성은 CSP(`style-src 'self'`)에 막히므로 폭은 렌더 뒤에
`el.style.setProperty()`로 넣는다. 원본의 `style="width:N%"`를 그대로 쓸 수 없다.

## 설정 화면 — 구현 (6b)

상태바 톱니 · 명령 팔레트 · `Ctrl+,` 로 연다. 원본에 없는 화면이라 원본의
`.dialog` 스타일 위에 얹었다.

내용은 JS가 채운다. 값이 설정에서 오고 절이 셋이라 마크업을 손으로 두면 화면과
저장값이 어긋나기 쉽다.

| 절 | 무엇 |
|---|---|
| 변환 | 새 문서의 기본 엔진·이미지 처리, 동시 실행 수, 파일 크기 상한, 프론트매터, 기본 저장 위치 |
| LLM | 프로바이더·모델·입력 모드·출력 언어·제한 시간, CLI 탐지 결과(실행 확인 포함)와 진단 리포트, 프롬프트 전문 |
| 일반 | 감시 폴더 관리, 테마, 버전·구성요소 라이선스 |

**값은 바꾸는 즉시 저장한다.** 확인 버튼이 없다 — 되돌릴 수 있는 설정뿐이고,
"적용"을 누르지 않아 설정이 안 먹었다고 헤매는 쪽이 더 흔한 실수다.

**기본값은 앞으로 들어올 문서에만 적용된다.** 화면에 그렇게 적었다. 이미 큐에 있는
문서를 건드리면 인스펙터에서 손댄 값이 조용히 날아간다.

Ollama를 고르면 모델이 드롭다운이 된다(`/api/tags`). 조회에 실패하면 자유 입력으로
돌아가고 사유를 함께 띄운다 — CLI 단독으로도 동작해야 한다. 루프백만 쓴다는 사실도
화면에 적는다 (결정 15).

## 캡션바 (build.25 반영)

원본 디자인의 `파일 · 편집 · 보기 · 도움말` 은 **마크업만 있고 클릭 핸들러가 없는
장식**이었다. 네이티브 메뉴도 없다 — `frame: false` 라 Windows 메뉴 자체가 존재하지
않는다. 쓰지 않을 것을 누를 수 있게 두면 사용자가 거기서 기능을 찾는다. 지웠다.

대신 하단 상태바의 톱니를 **우측 상단 `설정` 글자 버튼**으로 옮겼다(아이콘 없음).
설정을 여는 길 네 개 — 이 버튼, 명령 팔레트, `Ctrl+,`, 실패 카드의 "OCR 켜고 재시도"
— 는 모두 `openSettings()` 하나로 모이므로 잃는 경로가 없다.

드래그 영역은 오히려 넓어졌다. `.titlebar` 전체가 `drag` 이고 주 메뉴는 `no-drag` 로
**빼는** 쪽이었다.

**`design/index.html`(시각적 계약)과 의도적으로 갈라지는 첫 사례다.** 색 토큰 대조는
계속 원본을 따르고, 이 구조 차이만 예외로 둔다.
